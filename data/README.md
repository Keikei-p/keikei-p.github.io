# サービスデータ登録ルール

`services.js` は、診断・比較・詳細ページが共通で使うサービス情報の唯一のデータ置き場です。

## 登録の順番

1. 公式料金ページを確認する
2. 公式の提供条件・重要事項・エリア情報を確認する
3. サービス情報を `services.js` に追加する
4. `checkedAt` と `priceCheckedAt` を `YYYY-MM-DD` 形式で入れる
5. 確認した公式URLを `sourceUrls` に残す
6. アフィリエイト案件が確定した後だけ `affiliateUrl` を入れる

## 重要な考え方

- 未確認の項目は推測で埋めない
- `false` は「非対応」、`null` は「未確認」として使い分ける
- キャンペーン価格と通常価格を混ぜない
- 「実質○円」のような条件付き表現は、条件を同じ場所に明記できる場合だけ使う
- 通信速度は理論値と実測値を混同しない
- エリアは全国一律と決めつけず、公式の住所確認を促す

## 診断スコア

`fit` は広告報酬ではなく、利用者の条件との相性を表します。

スマホ系:
- `cost`: 料金重視
- `balance`: 料金と品質のバランス
- `quality`: 品質・サポート重視
- 質問タグ: `light-data`, `heavy-data`, `support-needed` など

Wi-Fi系:
- `H`: 光回線
- `R`: ホームルーター
- `M`: モバイルWi-Fi

スコアだけでなく、`matchReasons` に利用者へ見せる理由を書きます。

## 情報鮮度

`checkedAt` から90日を超えた情報は、画面上で再確認が必要な状態として扱える設計です。
料金改定やプラン変更を確認したら、データ本体と確認日を同時に更新してください。
